## UI 基盤

### ヘッダー機構の統一
- 現状、画面ヘッダーが **3 機構混在**:
  1. **Stack ナビヘッダー** … 推し編集 / プロフィール編集 / 会場 `[id]`（「会場モード」）等（`app/_layout.tsx` の `headerShown:true` 系）
  2. **共有 `ScreenHeader`** … list / trust / venue index（会場タブ）/ venue composer 等（`components/ScreenHeader.tsx`）
  3. **独自ステージ看板** … 会場 `[id]` の in-screen `venueContextHeader`（`app/venue/[id].tsx`、グラデ直置きの紫看板）
- 色・高さ・戻るボタンの扱いがバラバラで統一感がない（例: 会場 `[id]` は上端に白い Stack ナビバー＋その下に紫看板で二重、会場タブは共有 ScreenHeader を透過+明色 tint で紫化…と場当たり対応が積もっている）。
- **β1 後**、density 検証が回り始めてから **1 つの設計言語に統一**するリファクタ対象（ヘッダー抽象を 1 つに寄せ、色/高さ/戻る/右アクションを一貫化）。
- 全体を急に触ると回帰事故のリスクが高いため、**β1（7/20）には含めない**。
- 関連: 会場タブ紫化は additive prop（`ScreenHeader.tint` / `HeaderActions.color`）で暫定対応済み（build 13 予定）。統一時にこの暫定を正式設計へ吸収する。

### 会場モード「暗地×光源」拡張案（VENUE IGNITION）
β1 では背景の暗地化＋coral/orange 光源＋入場演出の最小2点のみ実装。以下は
density 実証後（Phase 1.5+）に検討する拡張。実装は未着手・記録のみ。
- **光の海**: 参加者を粒子として暗地に散らし、人数が「灯りの密度」で伝わる表現。
- **熱量リング**: 盛り上がっている会場ほど発光リングが強くなる（供給板の活性度可視化）。
- **Venue Pass**: 入場証的な UI（チェックイン状態の演出的表現）。
- **時間帯演出**: 開催時刻に応じた光量/色温度の変化。
- **点火レベル**: 会場の盛り上がり段階を「点火」メタファで段階表示。
- 前提: いずれも density（実参加者数・供給数）が伴って初めて意味を持つため、
  β1 の実データが溜まってから。現行の紫版バックアップは `docs/venue_color_backup.md`。
